# Dynamic account catalog and cached model metadata

Available models come from the authenticated `GET /api/oauth2/catalog` response. No bundled model or vendor allowlist limits that directory. Authorized model/group IDs and original upstream request IDs remain unchanged.

The adapter downloads the full public directory from [models.dev](https://models.dev/api.json?type=all) without account credentials. It caches the response for 24 hours in `$XDG_CACHE_HOME/lmm/models-dev-v1.json` (or the native platform cache directory). `LMM_MODELS_DEV_CACHE` and `LMM_MODELS_DEV_TTL_MS` can override the path and lifetime. Concurrent loads share one refresh; successful updates replace the cache atomically. Failed refreshes keep the last valid cached directory. A missing cache or unmatched model leaves metadata unknown and does not remove the authorized model.

Metadata matching normalizes case, punctuation, provider prefixes and dated aliases, with bounded typo tolerance. Ambiguous candidates remain unknown. Matching supplies metadata only: it never chooses an account group, changes a request ID or grants access to a model. A declared specialized non-chat type is retained in the authorized directory with a chat limitation even when its output modality is text. Public zero limits mean unknown and use the documented compatibility budget where the host requires a positive number. Explicit non-null server fields take priority over public reference fields. Explicit user limit overrides retain their documented priority.

LMM catalog prices and group/trust multipliers remain authoritative. Public reference pricing is not a wallet quote; missing account prices remain unknown. Discovery performs no paid model invocation. Account catalog JSON accepts up to 32 MiB without widening OAuth response limits. A failed account catalog request is an error; an empty successful catalog removes old models.

Zed settings admit every authorized OpenAI Chat Completions or Responses route whose known modalities permit text. Unknown or incomplete metadata uses labeled compatibility limits instead of removing the model. Server/public metadata supplies tools and images; optional `--models` provides explicit route-specific overrides. The running bridge refreshes catalog/settings on discovery and invocation. Prices remain in `lmm-zed catalog` and bridge discovery because the native picker has no price field.
